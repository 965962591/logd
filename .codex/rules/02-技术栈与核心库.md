# 02-技术栈与核心库

## 适用范围

本规则锁定 D:\tuning\tools\AE\logd 的 Rust workspace、引擎 crate、GPUI UI crate、第三方依赖、编译目标和发布形态。

## 规则条目

### R1: Rust 和 workspace 版本固定

**断言**：根 Cargo.toml 必须保持 workspace resolver = "2"、edition = "2021"、rust-version = "1.85"；开发机和 CI 的验证工具链固定为 rustc/cargo 1.96.0。出现其他 edition、缺少 rust-version 或未在锁定工具链上验证即违规。

**示例**：

~~~~toml
[workspace]
resolver = "2"
members = ["crates/logd-core", "crates/logd"]

[workspace.package]
edition = "2021"
rust-version = "1.85"
~~~~

**违规特征**：某个 crate 自行声明 edition = "2024"，或使用 nightly 专有 API 却没有同步更新 MSRV 和 CI。

### R2: GPUI 与 gpui-kit 版本固定

**断言**：UI crate 必须使用 GPUI 0.2.2；Longbridge gpui-kit 仓库必须固定到 v0.2.0 对应的 commit ca9d5b77e2f768b0f911999ee43c0b5e9104edc1。该仓库的实际 Cargo 包名是 gpui-component，代码 import 必须使用 gpui_component；浮动分支和未锁定版本均违规。

**示例**：

~~~~toml
[dependencies]
gpui = { version = "=0.2.2", default-features = false }
gpui-component = {
    git = "https://github.com/longbridge/gpui-kit.git",
    rev = "ca9d5b77e2f768b0f911999ee43c0b5e9104edc1",
    package = "gpui-component",
    version = "=0.2.0",
}
~~~~

~~~~rust
use gpui_component as gpui_kit;
~~~~

**违规特征**：写成 gpui-kit = "*"、gpui-component = { git = "...", branch = "main" }，或从其它同名 crate 引入组件。

### R3: 核心依赖版本基线固定

**断言**：引擎依赖必须与以下基线一致，并通过 Cargo.lock 固化解析结果：anyhow 1.0.102、thiserror 2.0.18、memchr 2.8.0、memmap2 0.9.11、aho-corasick 1.1.4、regex 1.12.3、rayon 1.12.0、quick-xml 0.36.2、encoding_rs 0.8.35、parking_lot 0.12.5、dirs 6.0.0。升级任何一个版本必须有性能或安全理由和测试记录。

**示例**：

~~~~toml
[workspace.dependencies]
memmap2 = "=0.9.11"
memchr = "=2.8.0"
aho-corasick = "=1.1.4"
regex = "=1.12.3"
rayon = "=1.12.0"
quick-xml = "=0.36.2"
encoding_rs = "=0.8.35"
~~~~

**违规特征**：在 crate Cargo.toml 中重新声明 memmap2 = "0.8"，或用未锁定的通配符版本覆盖 workspace 版本。

### R4: 平台目标显式覆盖 Windows 和 macOS

**断言**：发布和 CI 至少验证 x86_64-pc-windows-msvc、aarch64-apple-darwin、x86_64-apple-darwin；平台相关依赖必须放在 target 条件下，禁止将 Windows API 或 macOS framework 无条件引入 logd-core。

**示例**：

~~~~text
cargo check --workspace --target x86_64-pc-windows-msvc
cargo check --workspace --target aarch64-apple-darwin
cargo check --workspace --target x86_64-apple-darwin
~~~~

~~~~toml
[target.'cfg(target_os = "windows")'.dependencies]
windows = "=0.61.0"

[target.'cfg(target_os = "macos")'.dependencies]
objc = "=0.2.7"
~~~~

**违规特征**：在 logd-core 的普通 dependencies 中添加 windows、cocoa、metal，导致非目标平台也解析平台 API。

### R5: GPUI feature 必须按平台验证

**断言**：Windows 构建必须启用 GPUI 的 windows-manifest；macOS 构建必须验证 GPUI 的 Metal/Blade 路径和窗口创建。wayland、x11 不是本项目目标，不能为 Windows/macOS 无条件打开。

**示例**：

~~~~toml
[target.'cfg(target_os = "windows")'.dependencies.gpui]
version = "=0.2.2"
default-features = false
features = ["windows-manifest"]

[target.'cfg(target_os = "macos")'.dependencies.gpui]
version = "=0.2.2"
default-features = false
features = ["macos-blade"]
~~~~

**违规特征**：继续使用 GPUI 默认 wayland、x11 feature，或在 Windows 上启用仅 macOS 的 feature 而未经过 cargo check。

### R6: 发布形态和外部数据边界固定

**断言**：M0-M5 的发布产物是 Windows/macOS 原生便携式二进制；日志和 .tat 从本地文件读取，不引入后端服务、网络 API、SQLite 或运行时下载资源。新增网络或数据库依赖必须先修改本规则和架构评审记录。

**示例**：

~~~~text
logd.exe
logd            # macOS binary
tat/ae_log.tat  # local fixture, not bundled as a database
~~~~

**违规特征**：为了保存过滤器在 UI 中引入远程配置接口，或让 logd-core 启动 HTTP client。
