# 02-技术栈与核心库

## 适用范围

本规则锁定 D:\tuning\tools\AE\logd 的 Rust workspace、引擎 crate、GPUI UI crate、第三方依赖、编译目标和发布形态。

## 规则条目

### R1: Rust 和 workspace 版本固定

**断言**：根 Cargo.toml 必须保持 workspace resolver = "2"、edition = "2021"、rust-version = "1.85"；开发机和 CI 的验证工具链固定为 rustc/cargo 1.96.0。出现其他 edition、缺少 rust-version 或未在锁定工具链上验证即违规。

**示例**：

~~~~toml
[workspace]
resolver = "2"
members = ["crates/logd-core", "crates/logd"]

[workspace.package]
edition = "2021"
rust-version = "1.85"
~~~~

**违规特征**：某个 crate 自行声明 edition = "2024"，或使用 nightly 专有 API 却没有同步更新 MSRV 和 CI。

### R2: GPUI Git 跟随与锁文件审计

**断言**：UI crate 必须从 Zed Git 仓库获取 `gpui`/`gpui_platform`，从 Longbridge Git 仓库获取 `gpui-component`/`gpui-component-assets`，允许跟随 Git 更新；每次更新后 Cargo.lock 必须记录完整 commit，且 `gpui` 与组件库必须来自兼容提交。当前锁文件基线为 Zed `d7b9b38584cdb1e778a781548d32da35b2be1e96`、gpui-component `f517e74849c1e676bb03af90266e8449d01344f5`，包版本分别为 gpui 0.2.2、gpui_platform 0.1.0、gpui-component 0.5.2、gpui-component-assets 0.5.1。实际包名是 `gpui-component`，代码 import 必须使用 `gpui_component`。

**示例**：

~~~~toml
[dependencies]
gpui = { git = "https://github.com/zed-industries/zed", default-features = false }
gpui-component = {
    git = "https://github.com/longbridge/gpui-component",
    package = "gpui-component",
}
~~~~

~~~~rust
use gpui_component as gpui_kit;
~~~~

**违规特征**：把 `gpui-component` 当作 `gpui-kit` 引入，从其它同名 crate 引入组件，或更新 Git 依赖后 Cargo.lock 没有对应 commit。

### R3: 核心依赖版本基线固定

**断言**：引擎依赖必须与以下基线一致，并通过 Cargo.lock 固化解析结果：anyhow 1.0.102、thiserror 2.0.18、memchr 2.8.0、memmap2 0.9.11、aho-corasick 1.1.4、regex 1.12.3、rayon 1.12.0、quick-xml 0.36.2、encoding_rs 0.8.35、parking_lot 0.12.5、dirs 6.0.0。升级任何一个版本必须有性能或安全理由和测试记录。

**示例**：

~~~~toml
[workspace.dependencies]
memmap2 = "=0.9.11"
memchr = "=2.8.0"
aho-corasick = "=1.1.4"
regex = "=1.12.3"
rayon = "=1.12.0"
quick-xml = "=0.36.2"
encoding_rs = "=0.8.35"
~~~~

**违规特征**：在 crate Cargo.toml 中重新声明 memmap2 = "0.8"，或用未锁定的通配符版本覆盖 workspace 版本。

### R4: 平台目标显式覆盖 Windows 和 macOS

**断言**：发布和 CI 必须覆盖 x86_64-pc-windows-msvc、aarch64-pc-windows-msvc、x86_64-apple-darwin、aarch64-apple-darwin；平台相关依赖必须放在 target 条件下，禁止将 Windows API 或 macOS framework 无条件引入 logd-core。

**示例**：

~~~~text
cargo check --workspace --target x86_64-pc-windows-msvc
cargo check --workspace --target aarch64-pc-windows-msvc
cargo check --workspace --target aarch64-apple-darwin
cargo check --workspace --target x86_64-apple-darwin
~~~~

~~~~toml
[target.'cfg(target_os = "windows")'.dependencies]
windows = "=0.61.0"

[target.'cfg(target_os = "macos")'.dependencies]
objc = "=0.2.7"
~~~~

**违规特征**：在 logd-core 的普通 dependencies 中添加 windows、cocoa、metal，导致非目标平台也解析平台 API。

### R5: GPUI feature 必须按平台验证

**断言**：Windows 构建必须验证 GPUI 的 Windows 后端和窗口创建；macOS 构建必须验证 Metal/Blade 路径和窗口创建；四个目标均需至少完成 `cargo check`，实际宿主平台需完成 GPUI 手工冒烟。wayland、x11 不能为 Windows/macOS 无条件打开。

**示例**：

~~~~toml
[target.'cfg(target_os = "windows")'.dependencies.gpui]
git = "https://github.com/zed-industries/zed"
default-features = false
features = ["windows-manifest"]

[target.'cfg(target_os = "macos")'.dependencies.gpui]
git = "https://github.com/zed-industries/zed"
default-features = false
features = ["macos-blade"]
~~~~

**违规特征**：继续使用 GPUI 默认 wayland、x11 feature，或在 Windows 上启用仅 macOS 的 feature 而未经过 cargo check。

### R6: 发布形态和外部数据边界固定

**断言**：M0-M5 的发布产物是 Windows/macOS 原生便携式二进制；日志和 .tat 从本地文件读取，不引入后端服务、网络 API、SQLite 或运行时下载资源。新增网络或数据库依赖必须先修改本规则和架构评审记录。

**示例**：

~~~~text
logd.exe
logd            # macOS binary
tat/ae_log.tat  # local fixture, not bundled as a database
~~~~

**违规特征**：为了保存过滤器在 UI 中引入远程配置接口，或让 logd-core 启动 HTTP client。

### R7: 测试与性能基线固定

**断言**：引擎变更必须通过 `cargo test -p logd-core`；GPUI 变更必须完成实际宿主平台的手工启动冒烟；涉及索引、匹配、渲染或并发的变更必须使用 `crates/logd-core/examples/gen_big_log.rs` 生成大文件并记录首屏、全量索引、筛选耗时和 RSS。未执行对应层级验证不得标记里程碑完成。

**示例**：

~~~~text
cargo test -p logd-core
cargo run --release -p logd-core --example gen_big_log -- 10 D:/tmp/logd-big.log
cargo run --release -p logd
~~~~

**违规特征**：只编译成功就声称 GPUI 可用，或只用 KB 级夹具宣称满足 50GB 性能目标。
