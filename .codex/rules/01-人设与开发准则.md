# 人设与开发准则

## 适用范围

本规则适用于 `D:\tuning\tools\AE\logd` 的需求分析、架构设计、Rust 编码、GPUI UI、测试、性能验证和文档更新。

## 规则条目

### R1: 变更前读取权威上下文
**断言**：任何代码、依赖或规则变更前，必须读取 `doc/PLAN.md`、`doc/PROGRESS.md` 以及目标路径对应的 `.codex/rules/*.md`；未读取这些文件不得开始编辑。
**示例**：
```text
Get-Content doc/PLAN.md
Get-Content doc/PROGRESS.md
Get-Content .codex/rules/05-UI与组件规范.md
```
**违规特征**：未核对 50GB mmap/虚拟视口约束，就在 `crates/logd/src/app.rs` 中重写窗口布局。

### R2: 先定义可验证的行为契约
**断言**：每个新增公开函数、Entity、后台任务或菜单命令必须在相邻注释或规则中写明输入、输出、失败行为、线程归属和性能边界；仅写“支持”“优化”“尽量快”视为不合规。
**示例**：
```rust
/// 在 UI 线程打开本地日志；成功创建一个 Tab，失败保留当前视图并显示错误。
/// 不读取整个文件，首屏只允许索引 HEAD_BYTES。
pub fn open_log(&mut self, path: &Path, window: &mut Window, cx: &mut Context<Self>) {
    // ...
}
```
**违规特征**：新增 `open_file` 没有说明空文件、映射失败、重复标签和后台索引错误如何处理。

### R3: 遵守模块边界和最小修改原则
**断言**：一次变更只能触及完成需求所需的文件；引擎逻辑只能放在 `crates/logd-core/src/`，GPUI 逻辑只能放在 `crates/logd/src/`；不得覆盖、回滚或删除用户已有改动。
**示例**：
```text
标题栏改动范围：
crates/logd/src/app.rs
crates/logd/src/ui/title_bar.rs
crates/logd/src/platform.rs
```
**违规特征**：为了调整菜单样式修改 `crates/logd-core/src/matcher.rs`，或执行 `git reset --hard`、`git checkout -- .`。

### R4: 依赖/API 变更必须有版本证据
**断言**：新增或升级依赖必须同时更新 `Cargo.toml`、Cargo 生成的 `Cargo.lock` 和 `.codex/rules/02-技术栈与核心库.md`；GPUI Git 更新必须记录完整 commit SHA，并通过受影响目标的构建检查。
**示例**：
```toml
gpui = { git = "https://github.com/zed-industries/zed", rev = "d7b9b38584cdb1e778a781548d32da35b2be1e96" }
gpui-component = { git = "https://gh-proxy.org/https://github.com/longbridge/gpui-component", rev = "f517e74849c1e676bb03af90266e8449d01344f5" }
```
**违规特征**：只修改 Git URL 不更新锁文件，或把 `gpui-component` 替换成未审计的 `gpui-kit` crate。

### R5: 验证命令必须匹配变更层级
**断言**：引擎变更至少执行 `cargo fmt --all -- --check` 与 `cargo test -p logd-core`；GPUI 变更至少执行 `cargo check -p logd` 和宿主平台启动冒烟；跨平台变更必须检查 Windows/macOS 的 x86_64/aarch64 目标。
**示例**：
```text
cargo fmt --all -- --check
cargo test -p logd-core
cargo check -p logd --target x86_64-pc-windows-msvc
cargo check -p logd --target aarch64-pc-windows-msvc
cargo check -p logd --target x86_64-apple-darwin
cargo check -p logd --target aarch64-apple-darwin
```
**违规特征**：只运行核心单测，却声称无边框窗口、菜单和 Dock 已在四个平台验证。

### R6: 交付总结必须可追溯
**断言**：每次交付必须列出修改文件、行为变化、验证命令及结果、已知限制和下一步；文件引用必须使用仓库相对路径或绝对路径，必要时附行号。
**示例**：
```text
修改：crates/logd/src/app.rs；新增文件菜单和标题栏搜索。
验证：cargo test -p logd-core（通过）；cargo check -p logd（通过）。
限制：尚未完成 macOS 真机启动冒烟。
```
**违规特征**：只回复“UI 已完成”，不提供路径、测试结果或剩余风险。

### R7: 需求冲突必须停止扩张
**断言**：当新需求会引入网络服务、数据库、跨 crate 反向依赖或未授权破坏性操作时，必须先报告影响并等待明确授权；不得以实现便利为由扩大范围。
**示例**：
```text
本地架构约束：过滤器保存只能写本地 .tat/settings 文件；不得新增 HTTP client。
```
**违规特征**：为同步最近文件而擅自添加远程 API、后台服务或云端数据库。
