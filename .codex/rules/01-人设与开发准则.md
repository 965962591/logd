# 01-人设与开发准则

## 适用范围

本规则适用于 logd workspace 的所有需求分析、设计、编码、重构、测试和文档变更，覆盖 crates/logd-core、crates/logd、doc、tat 和 Cargo 配置。

## 规则条目

### R1: 先读取权威上下文

**断言**：任何代码或 Cargo 配置变更前，必须读取 doc/PLAN.md、doc/PROGRESS.md 以及与变更路径匹配的 .codex/rules/*.md；提交说明必须指出本次变更遵守的里程碑和规则。未读取或未说明即违规。

**示例**：

~~~~text
变更前置检查：
1. doc/PLAN.md：确认 M1 虚拟滚动的行为契约。
2. doc/PROGRESS.md：确认当前尚未完成 GPUI UI。
3. .codex/rules/02-技术栈与核心库.md：确认依赖和平台约束。
~~~~

**违规特征**：直接在 crates/logd/src/main.rs 增加 UI，却没有核对 PLAN 中的自建视口、行号精度和 gpui-kit 约束。

### R2: 约束先行，行为契约先于实现

**断言**：每个新增公开函数、组件或后台任务都必须在代码注释、相邻文档或变更说明中写明输入、输出、失败行为、线程归属和性能上限；只写“支持”“优化”“尽量快”等不可验证描述即违规。

**示例**：

~~~~rust
/// 返回原始行号对应的字节区间。
/// 输入：line < total_lines；输出：[start, end) 且不含 CRLF。
/// 越界：返回 None；复杂度：一次稀疏锚点定位加最多 1023 次换行扫描。
pub fn line_start(&self, data: &[u8], line: u64) -> Option<u64> {
    // implementation
}
~~~~

**违规特征**：新增 open_file() 但未说明空文件、UTF-16、文件被截断和映射失败时的行为。

### R3: 修改范围必须最小且可追溯

**断言**：每次变更只能触及完成目标所需的文件；不得覆盖或回滚用户已有改动，不得使用 git reset --hard、git checkout -- 或递归删除 workspace；手工编辑必须使用 apply_patch。

**示例**：

~~~~text
apply_patch <<'PATCH'
*** Update File: crates/logd/src/ui/theme.rs
...
PATCH
~~~~

**违规特征**：为了改一个按钮颜色重写整个 crates/logd/src/main.rs，或用 git checkout -- 恢复未由当前任务创建的文件。

### R4: 依赖和 API 变更必须有版本证据

**断言**：新增或升级依赖必须同时修改 Cargo.toml、Cargo.lock（由 Cargo 生成）和本规则中的版本记录；GPUI 及 gpui-component 允许跟随 Git 默认分支更新，但每次更新必须显式执行 `cargo update`、提交 Cargo.lock 中的完整 commit SHA，并完成受影响平台验证。

**示例**：

~~~~toml
gpui-component = {
    git = "https://github.com/longbridge/gpui-component",
    package = "gpui-component",
}

# 更新后 Cargo.lock 必须记录完整 commit，例如：
# f517e74849c1e676bb03af90266e8449d01344f5
~~~~

**违规特征**：只改 Cargo.toml 而没有更新 Cargo.lock，删除锁文件中的 Git commit，或更新 GPUI 后跳过目标平台构建检查。

### R5: 验证结果必须可复现

**断言**：代码变更完成后，必须执行与影响范围对应的格式检查、编译检查和测试；无法执行时必须记录完整命令、阻塞原因和未覆盖风险，不得声称“已验证”。

**示例**：

~~~~text
cargo fmt --all -- --check
cargo test -p logd-core
cargo check -p logd --target x86_64-pc-windows-msvc
cargo check -p logd --target aarch64-pc-windows-msvc
cargo check -p logd --target x86_64-apple-darwin
cargo check -p logd --target aarch64-apple-darwin
cargo run --release -p logd-core --example gen_big_log -- 10 D:/tmp/logd-big.log
# GPUI 手工冒烟：四平台至少各记录一次启动、打开、索引、筛选、关闭
~~~~

**违规特征**：只运行 cargo test -p logd-core，却在涉及 GPUI 的变更说明中声称 Windows/macOS UI 已通过验证。

### R6: 输出必须面向下一位实现者

**断言**：每次工作总结必须包含变更文件、行为变化、验证命令及结果、已知限制和下一步；引用代码时使用绝对路径或仓库相对路径加行号。

**示例**：

~~~~text
已修改 D:\tuning\tools\AE\logd\crates\logd-core\src\matcher.rs。
验证：cargo test -p logd-core，48 passed。
限制：GB18030 非 ASCII 正则仍按 PLAN.md 约定提示用户。
~~~~

**违规特征**：仅回复“完成了 UI”“性能已优化”，没有文件位置、测试结果或残余风险。
