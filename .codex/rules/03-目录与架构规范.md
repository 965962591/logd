# 目录与架构规范

## 适用范围

本规则覆盖 workspace crate 边界、日志引擎模块、GPUI 界面模块、平台适配、标题栏/菜单/Dock 组件和测试夹具路径。

## 规则条目

### R1: workspace crate 边界固定
**断言**：根 workspace 只能管理 `crates/logd-core` 与 `crates/logd`；`logd-core` 是无 UI 的纯引擎，`logd` 是 GPUI 应用；`logd-core/Cargo.toml` 不得出现 `gpui`、`gpui-component`、`rfd` 或 UI 状态依赖。
**示例**：
```text
D:\tuning\tools\AE\logd\
  Cargo.toml
  crates\logd-core\Cargo.toml
  crates\logd-core\src\
  crates\logd\Cargo.toml
  crates\logd\src\
```
**违规特征**：在 `crates/logd-core/src/index.rs` 引用 `gpui::Task`，或把 `Window`/`Entity` 放入 `Document`。

### R2: 引擎职责只能放在固定模块
**断言**：mmap/编码只在 `crates/logd-core/src/source.rs`；稀疏行索引只在 `index.rs`；匹配只在 `matcher.rs`；并行筛选只在 `scan.rs`；进度/取消只在 `progress.rs`；渲染坐标只在 `render.rs`；文档双坐标系只在 `document.rs`；`.tat` 只在 `tat.rs`；缓存只在 `cache.rs`。
**示例**：
```rust
// crates/logd-core/src/lib.rs
pub mod cache;
pub mod document;
pub mod index;
pub mod matcher;
pub mod progress;
pub mod render;
pub mod scan;
pub mod source;
pub mod tat;
pub mod viewport;
```
**违规特征**：在 `crates/logd/src/app.rs` 重新扫描换行，或在 UI 面板中解析 XML。

### R3: UI 目录按职责拆分
**断言**：GPUI 代码必须位于 `crates/logd/src/`；根状态在 `app.rs`，平台行为在 `platform.rs`，设置在 `settings.rs`；可复用 UI 组件放在 `ui/`，至少拆分 `title_bar.rs`、`menu_bar.rs`、`toolbar.rs`、`tabs.rs`、`filter_panel.rs`、`dock.rs`、`log_view.rs`、`theme.rs`。
**示例**：
```text
crates/logd/src/
  main.rs
  app.rs
  platform.rs
  settings.rs
  ui/
    title_bar.rs
    menu_bar.rs
    toolbar.rs
    tabs.rs
    filter_panel.rs
    dock.rs
    log_view.rs
    theme.rs
```
**违规特征**：把标题栏、最近文件、过滤器编辑表单和日志渲染继续堆进单个 `app.rs`。

### R4: 依赖方向只能由 UI 指向引擎
**断言**：只允许 `crates/logd -> logd-core`；禁止 `logd-core -> logd`、全局静态变量反向访问 UI 或引擎直接调用 `Window`；跨 crate 数据必须使用 `logd-core/src/lib.rs` 导出的类型。
**示例**：
```rust
use logd_core::{Document, Encoding, FilterSpec, LineIndex, MatcherSet, Progress};
```
**违规特征**：`logd-core` 中声明 `extern crate logd`，或 worker 捕获 `&mut Window`。

### R5: 公共引擎 API 必须统一 re-export
**断言**：UI 使用的引擎类型必须从 `crates/logd-core/src/lib.rs` 导出；UI 不得依赖 matcher/index/source 的私有深层路径。新增跨 crate 类型若无法通过 `logd_core::{...}` 导入即违规。
**示例**：
```rust
pub use document::{Document, RenderRow};
pub use index::{ChunkIndex, LineIndex, ANCHOR_STRIDE};
pub use matcher::{FilterSpec, HighlightMode, MatcherSet, Span, Verdict};
pub use source::{Encoding, FileSource};
```
**违规特征**：UI 使用 `logd_core::matcher::internal_*`，或在 `app.rs` 重复定义 `FilterSpec`。

### R6: 平台差异集中在适配层
**断言**：Windows/macOS 的主修饰键、无边框窗口选项、系统按钮、窗口拖动和文件对话框只能出现在 `crates/logd/src/platform.rs` 或其子模块，并使用 `cfg(target_os = ...)`；业务组件不得各自判断平台。
**示例**：
```rust
#[cfg(target_os = "windows")]
pub const PRIMARY_MODIFIER: Modifiers = Modifiers::CONTROL;

#[cfg(target_os = "macos")]
pub const PRIMARY_MODIFIER: Modifiers = Modifiers::COMMAND;
```
**违规特征**：`menu_bar.rs`、`title_bar.rs`、`tabs.rs` 分别绑定不同的 Ctrl/Cmd 逻辑。

### R7: 测试夹具和大文件生成路径固定
**断言**：真实 `.tat` 夹具只能放在 `tat/`；大日志生成工具只能放在 `crates/logd-core/examples/gen_big_log.rs` 或 `tools/`；测试生成的 10GB/50GB 文件不得进入 Git 跟踪目录。
**示例**：
```rust
const AE_LOG_TAT: &[u8] = include_bytes!("../../../tat/ae_log.tat");
```
**违规特征**：把大日志、缓存索引或临时生成文件提交到仓库源码目录。
