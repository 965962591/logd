# 03-目录与架构规范

## 适用范围

本规则覆盖 workspace 的 crate 边界、模块目录、依赖方向、公共 API、平台隔离和测试夹具位置。

## 规则条目

### R1: workspace 和 crate 边界固定

**断言**：根目录只通过 Cargo workspace 管理 crates/logd-core 和 crates/logd；logd-core 是无 UI 引擎，logd 是 GPUI 应用。logd-core 的 Cargo.toml 不得出现 gpui、gpui-component、rfd 或任何 UI 依赖。

**示例**：

~~~~text
D:\tuning\tools\AE\logd\
  Cargo.toml
  crates\logd-core\Cargo.toml
  crates\logd-core\src\
  crates\logd\Cargo.toml
  crates\logd\src\
~~~~

**违规特征**：在 crates/logd-core/src/index.rs 中引用 gpui::Task，或为了显示进度把 GPUI Entity 放进引擎结构体。

### R2: 引擎模块只能放在固定路径

**断言**：内存映射和编码只放在 crates/logd-core/src/source.rs；行索引只放在 index.rs；匹配只放在 matcher.rs；并行筛选只放在 scan.rs；进度/取消只放在 progress.rs；.tat 只放在 tat.rs；缓存只放在 cache.rs。相同职责的新文件必须先更新本规则。

**示例**：

~~~~rust
// crates/logd-core/src/lib.rs
pub mod cache;
pub mod index;
pub mod matcher;
pub mod progress;
pub mod scan;
pub mod source;
pub mod tat;
~~~~

**违规特征**：在 crates/logd/src/ui/log_view.rs 直接扫描换行并实现第二套行索引，造成 UI 和引擎语义分叉。

### R3: UI 模块按职责隔离

**断言**：GPUI 应用代码必须放在 crates/logd/src/；根视图在 app.rs；标签页文档状态在 doc.rs；窗口和最近文件设置在 settings.rs；组件和视图放在 ui/ 下，至少保持 log_view.rs、scrollbar.rs、tabs.rs、filter_panel.rs、toolbar.rs、theme.rs 的职责边界。

**示例**：

~~~~text
crates/logd/src/
  main.rs
  app.rs
  doc.rs
  settings.rs
  platform.rs
  ui/
    log_view.rs
    scrollbar.rs
    tabs.rs
    filter_panel.rs
    toolbar.rs
    theme.rs
~~~~

**违规特征**：把文件 mmap、.tat XML 解析或 rayon 扫描写进 ui/filter_panel.rs。

### R4: 依赖方向只能由 UI 指向引擎

**断言**：允许 crates/logd -> logd-core；禁止 logd-core -> logd，禁止通过全局静态变量反向访问 UI。跨 crate 数据必须使用 logd-core 的公开类型或明确的消息类型。

**示例**：

~~~~rust
// crates/logd/src/doc.rs
use logd_core::{FileSource, LineIndex, MatcherSet, Progress};
~~~~

**违规特征**：在 logd-core 中声明 extern crate logd，或让引擎直接调用 Window::refresh。

### R5: 公共类型通过 lib.rs 统一导出

**断言**：logd-core 外部使用的类型必须从 crates/logd-core/src/lib.rs re-export；UI 不得依赖深层私有模块路径。新增公共类型若无法从 lib.rs 导入即违规。

**示例**：

~~~~rust
// crates/logd-core/src/lib.rs
pub use index::{ChunkIndex, LineIndex, ANCHOR_STRIDE};
pub use matcher::{FilterSpec, HighlightMode, MatcherSet, Span, Verdict};
pub use source::{Encoding, FileSource};
~~~~

~~~~rust
// crates/logd/src/doc.rs
use logd_core::{Encoding, FileSource, LineIndex};
~~~~

**违规特征**：UI 直接使用 logd_core::matcher::private_helper，或在多个 UI 文件重复定义 FilterSpec。

### R6: 平台代码集中隔离

**断言**：Windows/macOS 差异只能出现在 crates/logd/src/platform.rs 或其子模块，并使用 cfg(target_os = "...")；引擎公共路径不得出现平台分支，除非该分支是文件系统语义所必需且有测试。

**示例**：

~~~~rust
#[cfg(target_os = "windows")]
pub const PRIMARY_MODIFIER: Modifiers = Modifiers::CONTROL;

#[cfg(target_os = "macos")]
pub const PRIMARY_MODIFIER: Modifiers = Modifiers::COMMAND;
~~~~

**违规特征**：在 tabs.rs、toolbar.rs 各自判断 cfg!(target_os = "macos")，导致快捷键和菜单行为不一致。

### R7: 测试夹具和生成工具路径固定

**断言**：真实 .tat 夹具只能放在 tat/；大文件生成工具只能放在 crates/logd-core/examples/gen_big_log.rs 或 tools/；测试不得把 10GB/50GB 文件写入 git 跟踪目录。

**示例**：

~~~~rust
const AE_LOG: &[u8] = include_bytes!("../../../tat/ae_log.tat");
~~~~

**违规特征**：把生成的 50GB sample.log 提交到仓库，或在 crates/logd/src/ 中生成测试数据。
