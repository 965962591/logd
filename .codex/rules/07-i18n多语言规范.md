# 07-i18n 多语言规范

## 适用范围

本规则覆盖 `crates/logd/src/` 中所有用户可见文本、菜单、快捷键提示、错误状态、空状态、进度状态和设置项。当前支持语言为简体中文 `zh-CN` 与英文 `en-US`；日志正文和过滤器文本属于用户数据，不得被翻译。

## 规则条目

### R1: 用户可见文本必须使用消息 key

**断言**：`crates/logd/src/` 的 UI 元素不得直接写中文或英文显示字符串；所有显示文本必须通过 `i18n::text("key")` 或等价的集中 API 获取。日志原文、文件名、路径和用户输入不适用此规则。

**示例**：

~~~~rust
use crate::i18n::text;

button(text("action.open_file"))
    .tooltip(text("tooltip.open_file"));
~~~~

**违规特征**：在 `toolbar.rs` 写 `.child("打开文件")`，或在错误分支写 `format!("文件打开失败: {error}")` 而没有消息 key。

### R2: 语言资源目录和 key 命名固定

**断言**：语言资源必须放在 `crates/logd/locales/zh-CN.toml` 和 `crates/logd/locales/en-US.toml`；key 使用小写点分层格式，且两个文件必须包含完全相同的 key 集合。新增 key 只允许通过资源文件提交。

**示例**：

~~~~text
crates/logd/
  locales/
    zh-CN.toml
    en-US.toml
~~~~

~~~~toml
# locales/zh-CN.toml
[action]
open_file = "打开文件"

# locales/en-US.toml
[action]
open_file = "Open file"
~~~~

**违规特征**：把语言文件放在 `tat/` 或 `doc/`，只在一种语言中添加 key，或使用 `OpenFileButton` 这类无法按层级扫描的 key。

### R3: 语言选择和回退策略唯一

**断言**：语言优先级必须为“用户设置 > 系统 locale > `zh-CN`”；不支持的 locale 必须先按语言前缀回退，再回退到 `zh-CN`。缺失 key 必须回退到 `en-US` 同名 key，仍缺失时显示 key 本身并记录诊断，不得 panic 或显示空字符串。

**示例**：

~~~~rust
pub fn resolve_locale(user: Option<&str>, system: &str) -> Locale {
    user.map(Locale::parse)
        .or_else(|| Locale::parse(system).ok())
        .unwrap_or(Locale::ZhCn)
}

pub fn text(key: &str) -> String {
    current().get(key)
        .or_else(|| fallback_en().get(key))
        .unwrap_or_else(|| key.to_owned())
}
~~~~

**违规特征**：语言切换后使用空字符串替代缺失翻译，或在多个组件各自实现不同的 locale 检测和 fallback。

### R4: 参数化消息不得拼接用户可见句子

**断言**：包含文件名、行号、数量、错误原因的文本必须使用带命名参数的消息模板；业务代码不得通过中英文片段拼接句子。参数值必须保持原始数据，不得作为 key 参与查找。

**示例**：

~~~~toml
# zh-CN.toml
[status]
matched_lines = "命中 {count} 行"
open_failed = "无法打开 {path}: {reason}"
~~~~

~~~~rust
text_args("status.matched_lines", [("count", count.to_string())]);
~~~~

**违规特征**：`format!("Matched " + &count.to_string() + " lines")`，或把完整文件路径插入消息 key。

### R5: 双语验证和布局约束必须进入测试基线

**断言**：每个 UI 里程碑至少在 `zh-CN` 与 `en-US` 各完成一次 GPUI 手工冒烟；资源校验必须检查 key 集合相等、格式化参数齐全、按钮和状态文本无裁切或溢出。任何新增 UI 文本缺少双语资源或验证记录即违规。

**示例**：

~~~~text
cargo test -p logd -- i18n
手工冒烟：zh-CN 启动/打开/索引/筛选/错误；en-US 启动/打开/索引/筛选/错误
~~~~

**违规特征**：只验证中文界面，英文界面出现 key 原文、按钮文字被裁切，或新增状态没有对应英文资源。
