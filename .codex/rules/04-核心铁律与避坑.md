# 04-核心铁律与避坑

## 适用范围

本规则覆盖 50GB 级日志的存储、索引、匹配、筛选、渲染、并发、取消、编码和 Windows/macOS 文件行为。

## 规则条目

### R1: 禁止把整个日志或每行加载进堆

**断言**：日志正文必须通过 memmap2 映射；任何路径不得构造“每行一个 String”或“每行一个 u64 偏移”的全量集合。50GB 文件的引擎堆内存目标必须低于 300MB，不含操作系统 page cache。

**示例**：

~~~~rust
let source = FileSource::open(path)?;
let data = source.data(); // borrowed mmap slice
let index = LineIndex::build_full(data, &progress);
~~~~

**违规特征**：std::fs::read(path) 后对全部内容 lines().map(str::to_owned).collect()，或生成长度等于 total_lines 的偏移数组。

### R2: 全局行号和滚动位置使用 u64

**断言**：文件字节偏移、总行数、原始行号、筛选命中行号和 anchor_line 必须使用 u64；f32 只允许表示视口内 pixel_offset 和最终绘制像素。不得用 total_lines * line_height 的 f32 保存全局滚动位置。

**示例**：

~~~~rust
pub struct ViewportState {
    pub anchor_line: u64,
    pub pixel_offset: f32,
}

let thumb_ratio = anchor_line as f64 / total_lines.max(1) as f64;
~~~~

**违规特征**：let scroll_y: f32 = line as f32 * 18.0，当行号超过约 93 万后出现跳行和抖动。

### R3: 索引必须稀疏且边界按整行对齐

**断言**：行索引必须使用 ANCHOR_STRIDE = 1024 的块内锚点；非末块起点和 end_byte 必须落在完整行边界；build_head 的部分结果必须通过 indexed_bytes 和 complete 标识，禁止将半行计入首屏。

**示例**：

~~~~rust
pub const ANCHOR_STRIDE: u64 = 1024;
let start = index.line_start(data, requested_line);
~~~~

**违规特征**：按固定字节切片后直接把切片首字节当作新行，或在 UI 中把 total_lines 当成精确值而忽略 complete == false。

### R4: 匹配在原始字节上完成

**断言**：筛选扫描必须在 FileSource 的原始 bytes 上使用 Aho-Corasick 和 regex::bytes；只有可见的约 60 行在渲染前解码。编码探测遵循 BOM、UTF-8、GB18030 顺序，UTF-16 必须报错。

**示例**：

~~~~rust
let matcher = MatcherSet::new(filters, source.encoding())?;
let visible = matcher.is_visible(&data[start as usize..end as usize]);
let text = source.decode(start, end);
~~~~

**违规特征**：为了匹配先把 50GB 转成一个 Unicode String，或用系统默认编码静默读取 GB18030。

### R5: include/exclude 和重叠匹配语义不可改变

**断言**：可见性必须满足“无 include 或命中 include”且“未命中 exclude”；字面量集合必须用 find_overlapping_iter 和 MatchKind::Standard；CRLF 的 \\r 在匹配前剥除，末尾无换行的一行也必须扫描。

**示例**：

~~~~rust
let visible = (no_include || include_hit) && !exclude_hit;
for m in ac.find_overlapping_iter(line) {
    spans.push(Span { start: m.start(), end: m.end(), filter: map[m.pattern().as_usize()] });
}
~~~~

**违规特征**：使用非重叠 find_iter 导致 abc 与 bcd 在 abcd 中只报告一个命中，或把 excluding 过滤器当作额外 include。

### R6: 并行任务必须可取消并报告进度

**断言**：全量索引和筛选必须复用 index 的 chunk、使用 rayon 并行，并通过 Progress 原子量报告 done/total；至少每 4096 行检查取消，取消后不得向 UI 发布“完成”状态。

**示例**：

~~~~rust
let progress = Arc::new(Progress::default());
let outcome = scan_all(data, &index, &matcher, &progress);
if progress.is_cancelled() {
    return TaskResult::Cancelled;
}
~~~~

**违规特征**：后台线程无限运行、UI 只能关闭窗口才能停止，或取消后仍把部分 Vec<u64> 当作完整筛选结果。

### R7: 渲染只处理视口窗口

**断言**：日志视图每次渲染只读取可见行加 2 行缓冲；默认每行最多解码/布局 4096 个字符，超长行显示截断标记并提供展开动作；禁止用 uniform_list 直接创建数亿行元素。

**示例**：

~~~~rust
let visible_count = (viewport_height / line_height).ceil() as usize + 2;
index.line_spans(data, viewport.anchor_line, visible_count, &mut spans);
~~~~

**违规特征**：把 total_lines 传给 children()，或对一条几百 KB 的 dump 行无上限创建 StyledText。

### R8: mmap 文件必须视为静态输入

**断言**：当前版本打开文件后不得自动 tail 或假设文件长度增长；检测到外部截断、映射失败或读取区间越界必须显示可操作错误。Windows 和 macOS 都必须覆盖空文件路径。

**示例**：

~~~~rust
match FileSource::open(path) {
    Ok(source) => open_document(source),
    Err(error) => show_error(error),
}
~~~~

**违规特征**：文件被日志进程截断后继续访问旧 mmap，或吞掉映射异常显示空白文档。
