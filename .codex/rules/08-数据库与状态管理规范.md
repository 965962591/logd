# 数据库与状态管理规范

## 适用范围

本规则覆盖 `crates/logd/src/` 的 GPUI Entity/Context 状态、标签页、过滤器、Dock 布局、编辑缓冲、索引/筛选后台任务和本地设置。本项目不使用 SQLite、远程数据库或网络状态同步。

## 规则条目

### R1: 可变 UI 状态统一归属 GPUI Entity
**断言**：可变 UI 状态必须由 GPUI `Entity`/`Context` 管理；禁止 `static mut`、全局可变单例和跨组件互相写字段；组件只能通过事件或 Entity update 修改状态。
**示例**：
```rust
pub struct AppState {
    pub tabs: Vec<Entity<LogDocument>>,
    pub active_tab: usize,
    pub locale: Locale,
}

let app = cx.new(|_| AppState::default());
```
**违规特征**：`tabs.rs` 与 `log_view.rs` 各自维护 active 行号，或使用 `static CURRENT_DOCUMENT`。

### R2: 大对象使用 Arc/借用，UI 不复制日志
**断言**：`FileSource`、`LineIndex`、筛选结果和跨任务只读数据必须通过 `Arc` 或借用传递；渲染路径只能为可见单行创建临时 `Cow/String`；编辑只保存增量缓冲。
**示例**：
```rust
pub struct LogDocument {
    pub source: Arc<FileSource>,
    pub index: Arc<LineIndex>,
    pub matches: Option<Arc<Vec<u64>>>,
    pub edits: Vec<EditBuffer>,
}
```
**违规特征**：`source.data().to_vec()`，或每次滚动都 clone 完整 matches/日志正文。

### R3: 标签页状态独立，过滤器共享策略显式
**断言**：每个 Tab 必须独立拥有 source、index、matches、viewport、encoding、编辑缓冲和 task 状态；默认过滤器由 `LogdApp` 保存共享快照；用户选择分离后才复制 `Vec<FilterSpec>`；关闭 Tab 必须释放任务句柄和 mmap Arc。
**示例**：
```rust
pub struct TabState {
    pub document: Entity<LogDocument>,
    pub path: PathBuf,
    pub filters: FilterScope,
}

pub enum FilterScope {
    Shared,
    Detached(Vec<FilterSpec>),
}
```
**违规特征**：切换标签沿用上一个文件的 anchor，或修改共享过滤器时覆盖已分离标签。

### R4: 后台任务通过明确消息回传
**断言**：索引、筛选和大文件刷新线程只能发送消息，不能直接调用 Window、Entity 或组件；消息至少区分进度、渐进结果、完成、取消和错误。
**示例**：
```rust
pub enum TaskMessage {
    Progress { done: u64, total: u64 },
    IndexReady(Arc<LineIndex>),
    MatchesPrefix(Arc<Vec<u64>>),
    Completed,
    Cancelled,
    Failed(String),
}
```
**违规特征**：rayon worker 捕获 `&mut Window`，或用 `Option<Vec<u64>>` 同时表示运行中和 0 命中。

### R5: 每个任务只有一个权威取消来源
**断言**：每个后台任务必须持有独立 `Arc<Progress>`；UI 取消只能调用 `Progress::cancel()`；worker 至少每 4096 行检查 `is_cancelled()`，取消后不得发布 `Completed`。
**示例**：
```rust
pub struct TaskHandle { pub progress: Arc<Progress> }

impl TaskHandle {
    pub fn cancel(&self) { self.progress.cancel(); }
}
```
**违规特征**：同时维护 bool、channel 和 Progress 三套取消标记，导致取消后仍发布完成结果。

### R6: 状态机必须区分未完成、空结果和失败
**断言**：索引必须区分 `complete == false` 与 `complete == true`；筛选必须区分 `AllVisible`、`Matched(empty)`、`Running`、`Cancelled`、`Failed`；状态转换只能由对应 TaskMessage 驱动。
**示例**：
```rust
pub enum FilterState {
    NotStarted,
    Running { fraction: f32 },
    AllVisible,
    Matched(Arc<Vec<u64>>),
    Cancelled,
    Failed(String),
}
```
**违规特征**：空 Vec 同时表示没有过滤器、尚未收到结果和筛选完成但没有命中。

### R7: Dock、菜单和编辑状态必须小型持久化
**断言**：`settings.rs` 只能保存窗口尺寸、最近文件路径、上次 `.tat`、语言、编码覆盖、Dock 布局和过滤器面板可见性等小型元数据；不得保存 mmap、完整 LineIndex、完整命中数组或日志正文；设置损坏必须回退默认值并显示非阻塞提示。
**示例**：
```rust
pub struct Settings {
    pub window_width: u32,
    pub window_height: u32,
    pub recent_files: Vec<PathBuf>,
    pub last_tat: Option<PathBuf>,
    pub locale: String,
    pub dock_layout: DockLayout,
}
```
**违规特征**：把日志正文写进 settings.json，或设置文件损坏时阻止应用启动。

### R8: 菜单命令是跨组件状态入口
**断言**：文件打开/刷新/最近文件、视图切换、过滤器 CRUD、编辑保存、复制和 Dock 切换必须先转换为 `MenuCommand`/`AppAction`，再由 `LogdApp` 分发；组件不得直接修改另一个组件的私有字段。
**示例**：
```rust
pub enum AppAction {
    Open(PathBuf),
    RefreshActive,
    SetViewMode(ViewMode),
    AddFilter(FilterSpec),
    SaveFilter,
    SetDockLayout(DockLayout),
}
```
**违规特征**：过滤器行点击直接改 `LogView` 内部 matcher，或标题栏绕过 App 状态写设置文件。
