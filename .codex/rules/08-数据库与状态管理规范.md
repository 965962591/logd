# 08-数据库与状态管理规范

## 适用范围

本规则覆盖 crates/logd/src/ 的 GPUI Entity/Context 状态、LogDocument、标签页、过滤器、索引和筛选后台任务；本项目当前不使用 SQLite 或远程数据库。

## 规则条目

### R1: UI 状态归属 GPUI Entity

**断言**：可变 UI 状态必须归属于 GPUI Entity/Context 管理；不得使用 static mut、全局可变单例或散落在多个组件中的互相写入字段。组件只能通过事件或 Entity update 修改文档状态。

**示例**：

~~~~rust
pub struct LogDocument {
    pub source: Arc<FileSource>,
    pub index: LineIndex,
    pub matches: Option<Arc<Vec<u64>>>,
    pub viewport: ViewportState,
    pub status: DocumentStatus,
}

cx.new(|_| LogDocument::new(source))
~~~~

**违规特征**：tabs.rs 和 log_view.rs 各自维护 active_line，或使用 static CURRENT_DOCUMENT 保存活动文档。

### R2: 大对象共享所有权，禁止 UI 线程复制

**断言**：FileSource、筛选结果和跨任务只读数据必须通过 Arc 或借用传递；渲染路径不得 clone mmap 内容、完整行文本或命中数组。只有单行可见文本允许生成临时 Cow/String。

**示例**：

~~~~rust
pub struct LogDocument {
    pub source: Arc<FileSource>,
    pub matches: Option<Arc<Vec<u64>>>,
}

let line = document.source.decode(start, end);
~~~~

**违规特征**：let copy = source.data().to_vec()，或每次滚动都 matches.as_ref().unwrap().to_vec()。

### R3: 后台任务必须通过明确消息回传

**断言**：索引和筛选线程只能发送 TaskMessage，不能直接调用 Window、Entity 或组件方法；消息必须区分进度、渐进结果、完成、取消和错误。

**示例**：

~~~~rust
pub enum TaskMessage {
    Progress { done: u64, total: u64 },
    IndexReady(Arc<LineIndex>),
    MatchesPrefix(Arc<Vec<u64>>),
    Completed,
    Cancelled,
    Failed(String),
}
~~~~

**违规特征**：rayon worker 捕获 &mut Window，或用 Option<Vec<u64>> 既表示“尚未完成”又表示“完成但 0 命中”。

### R4: 取消信号只有一个权威来源

**断言**：每个后台任务必须持有独立的 Arc<Progress>；UI 取消动作只能调用 Progress::cancel()，worker 至少每 4096 行检查 is_cancelled()，并在完成消息前确认未取消。

**示例**：

~~~~rust
pub struct TaskHandle {
    pub progress: Arc<Progress>,
}

impl TaskHandle {
    pub fn cancel(&self) {
        self.progress.cancel();
    }
}
~~~~

**违规特征**：同时使用 bool、channel 关闭和 Progress 三套取消标记，导致 UI 显示已取消而 worker 继续发布完成结果。

### R5: 标签页状态独立，过滤器共享策略显式

**断言**：每个标签页必须拥有独立的 source、index、matches、viewport、encoding 和 task 状态；过滤器默认由 App 维护一份共享快照，用户选择“分离”后才复制 FilterSpec 列表。标签关闭必须释放该页的任务句柄和 Arc。

**示例**：

~~~~rust
pub struct AppState {
    pub tabs: Vec<Entity<LogDocument>>,
    pub active_tab: usize,
    pub shared_filters: Arc<Vec<FilterSpec>>,
}
~~~~

**违规特征**：切换标签后沿用上一个文件的 anchor_line，或修改一个标签的过滤器却静默改变另一个已分离标签。

### R6: 筛选视图保留原始行号

**断言**：matches 中保存的值必须是源文件原始 u64 行号；仅显示筛选结果时，视口索引的是 matches 的位置，但传给 LineIndex 的行号必须取 matches[position]，不能使用 position 作为行号。

**示例**：

~~~~rust
let source_line = matches.get(filtered_position).copied()?;
index.line_spans(data, source_line, visible_count, &mut spans);
render_line_number(source_line + 1);
~~~~

**违规特征**：筛选后第一行显示为 1 而实际命中原文件第 420000000 行，或用 filtered_position 查询 LineIndex。

### R7: 状态迁移必须保留“未完成”和“空结果”的区别

**断言**：索引必须区分 complete == false 与 complete == true；筛选必须区分 AllVisible、Matched(empty)、Running、Cancelled 和 Failed；任何状态转换只能由对应 TaskMessage 驱动。

**示例**：

~~~~rust
pub enum FilterState {
    NotStarted,
    Running { progress: ProgressSnapshot },
    AllVisible,
    Matched(Arc<Vec<u64>>),
    Cancelled,
    Failed(String),
}
~~~~

**违规特征**：用空 Vec 同时表示“没有过滤器”“尚未收到结果”和“筛选完成但没有命中”。

### R8: 设置持久化只保存小型可序列化数据

**断言**：settings.rs 只能持久化窗口尺寸、最近文件路径、上次 .tat 路径、主题和编码覆盖等小型元数据；不得持久化 mmap 内容、完整 LineIndex 或完整日志。设置读写失败必须回退默认值并显示非阻塞提示。

**示例**：

~~~~rust
#[derive(Serialize, Deserialize, Default)]
pub struct Settings {
    pub window_width: u32,
    pub window_height: u32,
    pub recent_files: Vec<PathBuf>,
    pub last_tat: Option<PathBuf>,
    pub theme: String,
}
~~~~

**违规特征**：把 50GB 文件正文写入 settings.json，或设置文件损坏时阻止应用启动。
